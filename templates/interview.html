YOUR 3–5 MINUTE EXPLANATION

Walk an interviewer from problem to result

  1. Problem: “I built a next-month credit-card default predictor using UCI’s historical Taiwan credit-card data. It is not fraud detection: fraud asks whether a transaction is unauthorised; default prediction estimates whether a client may fail to repay.”
  2. Value: “A lender could use a risk score to prioritise human review, support, or affordability investigation. Missing risk can increase losses; flagging safe customers creates cost and potential harm. That is why accuracy alone is not enough.”
  3. Data and EDA: “The data contains 30,000 historical client rows and a binary next-month default label. Defaults are 22.12%. I checked schema, missingness, duplicates, distributions, class balance, repayment-status default rates, correlations, and a heatmap. Recent repayment behaviour was strongly associated with default, but I did not treat association as causation.”
  4. Features: “I created only past-looking features: latest-bill-to-limit utilisation, six payment-to-bill ratios, average/max delay, delay count, early-payment flag, average bills and payments, six-month bill/payment trends, and a high-utilisation flag.”
  5. Pipeline: “Feature engineering, imputation, scaling, encoding, and the estimator are saved together in a pipeline. That gives training and Flask inference the same transformations and prevents fitting preprocessing on held-out folds.”
  6. Experiment: “I used a stratified 60/20/20 train/validation/test split. I screened 13 model families using five-fold CV on training data; I tuned the top four; I compared native imbalance handling with random oversampling and SMOTENC; I selected a threshold on validation data; then I evaluated once on the untouched test set.”
  7. Conclusion: “Tuned XGBoost won mean CV average precision at {{ "{:.4f}".format(summary.benchmark.tuning[0].cv_average_precision) }}. Native weighting beat the resampling options. The validation threshold is {{ "{:.1%}".format(summary.model.threshold) }}. On the held-out test set, ROC-AUC is {{ "{:.4f}".format(summary.model.test_metrics.roc_auc) }}, average precision {{ "{:.4f}".format(summary.model.test_metrics.average_precision) }}, precision {{ "{:.4f}".format(summary.model.test_metrics.precision) }}, recall {{ "{:.4f}".format(summary.model.test_metrics.recall) }}, and F1 {{ "{:.4f}".format(summary.model.test_metrics.f1) }}.”
CONCEPTS USED

What happens to one customer record

CSV/form inputs→validate→engineer features→impute / encode / scale→probability model→thresholded review flag
Imputation, encoding, and scaling in plain English

Imputation replaces a missing numeric input with the training median and a missing category with the most common training category. The source itself has no missing cells; this is defensive pipeline design. One-hot encoding turns a category such as education into separate yes/no columns, so code 2 is not treated as twice code 1. Standardisation centres and scales numeric values using training-fold statistics; it matters for linear/distance models and makes comparisons consistent.

Feature engineering: what was added and why?

Utilisation = latest bill ÷ credit limit, so bills have context. Payment ratios compare each payment to its bill. Average/max delay and months with delays compress six repayment-status months. Early payment and high utilisation are behavioural flags. Average bill/payment provide typical exposure/repayment. Bill/payment trends are six-month slopes, capturing direction rather than only one month.

What is leakage, and how was it prevented?

Leakage means information unavailable at prediction time has influenced training or evaluation. The split comes before fitting. All transformations and samplers are inside pipelines, so a CV fold learns from its training rows only. Feature engineering uses only prior history. Validation selects the threshold; the test split is opened only after decisions are fixed.

ALL 13 SCREENED MODELS

What was tried, what it means, and why it mattered

Every candidate used the same engineered inputs and five stratified folds. The number shown is initial mean CV average precision. A weaker model is still useful evidence: it tests an assumption and establishes a comparison point.

Dummy prior baseline — AP 0.2212. Learns nothing; it predicts the default prevalence. This is the no-skill reference. A model must beat it to show useful ranking signal.
Logistic Regression — AP 0.5073. Adds weighted feature contributions and passes them through a sigmoid to make a probability. It is fast, interpretable, and a strong linear baseline; it misses nonlinear interactions unless they are engineered. Balanced class weights and regularisation C were used.
Gaussian Naive Bayes — AP 0.4863. Uses Bayes’ rule, assuming each feature’s distribution is Gaussian and features are conditionally independent. Bills and payments are correlated, so that simplifying assumption is often too strong.
Calibrated Linear SVM — AP 0.5044. Finds a linear separating boundary with the largest margin. Raw SVM scores are not probabilities, so sigmoid calibration converts them to probability-like outputs. Useful linear comparison; limited for nonlinear interactions.
K-Nearest Neighbours — AP 0.4249. A new case is predicted from nearby historical cases. It tests local similarity, but many engineered dimensions make “near” less reliable; it depends heavily on scaling. Neighbour count, distance, and weighting were searched.
Decision Tree — AP 0.2909. Repeated yes/no splits such as “is utilisation high?” are intuitive but a single tree is unstable and easily overfits. Depth and leaf size were tuned.
Random Forest — AP 0.5404. Averages many randomised trees trained on bootstrapped data and feature subsets. This lowers a single tree’s variance and captures nonlinear relationships, at the cost of more complexity and less direct interpretation.
Extra Trees — AP 0.5231. Similar to a random forest but injects more random split selection. Extra randomness can reduce variance but may miss useful split structure.
AdaBoost — AP 0.5357. Trains weak learners sequentially, putting more focus on earlier errors. It can improve simple learners but may be sensitive to noisy points.
Gradient Boosting — AP 0.5629. Adds trees sequentially to reduce remaining loss. It was the strongest initial screen and tuned to AP 0.5641, extremely close to the final winner.
Histogram Gradient Boosting — AP 0.5567. Bins values into histograms before split search, making boosting efficient for tabular data. It was competitive but not top after tuning.
CatBoost — AP 0.5551. A regularised boosted-tree method known for categorical-feature handling. It used automatic class weights and was tuned to AP 0.5626. It did not win under this consistent, preprocessed experiment.
XGBoost — tuned AP 0.5652, selected. Regularised gradient boosting: shallow trees are added sequentially, each improving errors from prior trees. The winning settings were 500 trees, depth 3, learning rate 0.02, 70% row subsampling, and minimum child weight 1. These controls seek useful nonlinear patterns without overly complex trees.
HOW WE GOT THE RESULT

Screening, tuning, imbalance, thresholding

18,000 training rows→5-fold screen→tune top 4→balance ablation→validation threshold→6,000-row test once
What is stratified five-fold cross-validation?

The training data is split into five parts with similar default rates. The model trains on four and scores the fifth, repeating until every part was held out once. Mean performance is more robust than a single lucky split.

What is hyperparameter tuning?

Hyperparameters are settings chosen before training: depth, learning rate, tree count, regularisation, or neighbour count. RandomizedSearchCV samples allowed combinations and evaluates each with CV. It tunes the top four screen finalists, using average precision as the selection score—not final-test results.

Why test three imbalance approaches?

Native uses XGBoost’s class weighting so default errors matter more. Random oversampling duplicates minority/default training rows. SMOTENC synthesises minority rows while respecting specified categories. Measured AP: native {{ "{:.4f}".format(summary.benchmark.balance_strategy_ablation[0].mean_average_precision) }}, random oversampling {{ "{:.4f}".format(summary.benchmark.balance_strategy_ablation[1].mean_average_precision) }}, SMOTENC {{ "{:.4f}".format(summary.benchmark.balance_strategy_ablation[2].mean_average_precision) }}. Native won, so it was retained. Resampling only occurs inside training folds.

Why is the threshold {{ "{:.1%}".format(summary.model.threshold) }}, not 50%?

The model outputs a score; a threshold turns it into an action flag. A lower threshold usually catches more defaults (recall rises) but flags more safe people (precision falls). This prototype maximised validation F1, the harmonic mean of precision and recall. A production bank should set it with business costs, review capacity, fairness, and policy—not blindly use 0.5.

LIKELY INTERVIEW INTERRUPTIONS

Questions and strong honest answers

Why XGBoost over CatBoost or Gradient Boosting?

Answer: “I did not choose it beforehand. I screened 13 candidates, tuned the top four under the same five-fold CV, and selected highest mean average precision. XGBoost was {{ "{:.4f}".format(summary.benchmark.tuning[0].cv_average_precision) }}, narrowly above Gradient Boosting {{ "{:.4f}".format(summary.benchmark.tuning[1].cv_average_precision) }} and CatBoost {{ "{:.4f}".format(summary.benchmark.tuning[2].cv_average_precision) }}. The margin is small, so it is the winner for this protocol, not universally best.”

Why average precision rather than accuracy or only ROC-AUC?

Answer: “A no-default model gets about 77.88% accuracy but catches no defaults. ROC-AUC is useful broad ranking evidence, but average precision concentrates on how trustworthy high-risk/default rankings are in an imbalanced setting. I still report all threshold and probability-quality metrics.”

Why precision over recall—or recall over precision?

Answer: “It depends on the workflow. Higher recall finds more defaults but increases false review flags. Higher precision gives fewer, more credible flags but misses risk. I used validation F1 as a neutral technical rule; a real policy would add intervention costs, human capacity, fairness evidence, and regulation.”

What is data leakage?

Answer: “Leakage is future or held-out information affecting training. I split before fitting, keep transformations and samplers inside CV pipelines, use only historic inputs for features, select threshold on validation, and use test once at the end.”

Why did SMOTENC not win?

Answer: “Imbalance techniques are tested, not assumed. For this XGBoost experiment native class weighting had the highest CV AP; oversampling and SMOTENC reduced it. Keeping the native method is evidence-led and avoids synthetic data when it does not improve the target metric.”

What are the project’s biggest limits?

Answer: “It is a historical academic dataset, not current production evidence. It lacks a time-based deployment validation, live outcome feedback, fairness/subgroup analysis, a cost policy, security/monitoring, and governance. I would never turn this offline result into automatic credit action.”

Closing line: “This project demonstrates a reproducible ML lifecycle: data understanding, past-only features, leakage-safe pipelines, broad model comparison, measured threshold trade-offs, a deployed inference path, and honest limits.”
