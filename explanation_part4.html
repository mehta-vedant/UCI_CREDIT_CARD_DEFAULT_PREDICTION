What is a Classification Model?

Before diving into each algorithm, let's understand what classification means in machine learning.

The Core Idea

Imagine you're a bank manager deciding whether a loan applicant will repay or default. Over the years, you've seen thousands of applicants: their income, credit history, employment status, and whether they eventually repaid. After studying these patterns, you develop an intuition: "People with high income, long credit history, and stable jobs tend to repay."

A classification model does exactly this — but mathematically. It learns patterns from historical labeled data (past outcomes) and uses those patterns to predict the category of new, unseen data points.

Real-World Analogy

"Classification is like a doctor learning from thousands of patient cases. After seeing enough patients — their symptoms, test results, and diagnoses — the doctor can look at a new patient and say: 'Based on what I've seen before, this pattern looks like Disease A, not Disease B.' The more cases the doctor has studied, the more accurate their diagnosis becomes."

In our project, the classification task is: Given a credit card transaction, predict whether it is fraudulent (1) or legitimate (0).

Types of Classification Models

Linear Models

Draw a straight line (or hyperplane) to separate classes. Simple, fast, interpretable.
Logistic Regression

Tree-Based Models

Create decision trees by splitting data on feature thresholds. Non-linear, interpretable.
Decision Trees

Ensemble Models

Combine multiple models for better predictions. Best performance on tabular data.
Random Forest, XGBoost, CatBoost, Gradient Boosting, AdaBoost

Distance-Based Models

Classify by similarity to neighboring data points. Simple but slow on large datasets.
KNN, SVM

Our project uses 1 Linear model (Logistic Regression) and 5 Ensemble models (Random Forest, Gradient Boosting, XGBoost, CatBoost, AdaBoost). Ensemble methods consistently outperform others on tabular/structured data.

Logistic Regression

Linear Model Baseline

How It Works

Logistic Regression is the simplest and most interpretable classification algorithm. Despite its name, it's used for classification, not regression. It works by fitting a linear equation to the input features and then passing the output through a sigmoid function that squashes the result into a probability between 0 and 1.

Mathematically, it computes: z = w₁x₁ + w₂x₂ + ... + wₙxₙ + b (a weighted sum), then applies the sigmoid function: P(y=1) = 1 / (1 + e⁻ᶻ). If P(y=1) > 0.5, predict fraud; otherwise, predict legitimate.

Real-World Analogy

"Imagine you're trying to separate marbles into two groups on a table using a straight stick. You slide the stick around until it best separates the red marbles from the blue ones. The stick is the decision boundary. Logistic Regression does the same thing, but in high-dimensional space — it draws the best straight line (or hyperplane) to separate fraud from legitimate transactions based on their features like amount, time, and V1-V28."

Visual: The Sigmoid Function

The sigmoid curve transforms any real number into a probability. Values far left → near 0 (legitimate), values far right → near 1 (fraud). The 0.5 threshold decides the classification.

Strengths
  • Extremely fast to train
  • Fully interpretable — each feature has a weight
  • Outputs calibrated probabilities
  • Works well as a baseline
  • Less prone to overfitting with regularization
  • Excellent when classes are linearly separable
Weaknesses
  • Cannot capture non-linear relationships
  • Assumes features are independent
  • Sensitive to outliers
  • Requires feature scaling
  • Poor performance on complex patterns
  • Struggles with high-dimensional interactions

Hyperparameters We Tuned

Parameter Values Tested What It Controls
C 0.1, 1.0, 10.0 Regularization strength. Smaller C = stronger regularization (simpler model, less overfitting). Larger C = weaker regularization (complex model, risk of overfitting). It's the inverse of lambda (λ).

Logistic Regression serves as the baseline model. Every ML project needs a simple benchmark — if complex models can't significantly outperform a straight line, something is wrong with the data or approach. It also provides interpretable coefficients showing which features drive fraud detection.

Random Forest Classifier

Ensemble (Bagging) 3rd Place

How It Works

Random Forest is a bagging ensemble method that builds hundreds of decision trees, each trained on a different random subset of the data and features. When making a prediction, every tree votes and the majority wins. This is called bootstrap aggregation (bagging).

Each tree in the forest is intentionally different: it sees a random sample of rows (with replacement) and at each split, considers only a random subset of features. This randomness prevents overfitting — individual trees may overfit to noise, but when hundreds vote together, the noise cancels out and only the true signal remains.

Real-World Analogy

"Imagine you need to estimate the population of a city. Instead of asking one statistician, you ask 100 independent experts, each of whom only has access to partial information. Some may overestimate, some may underestimate, but when you average their answers, the errors cancel out and you get a remarkably accurate estimate. That's Random Forest — many imperfect trees voting together produce a strong prediction."

Gradient Boosting Classifier

Ensemble (Boosting) 4th Place

How It Works

Gradient Boosting builds trees sequentially, where each new tree specifically focuses on the errors (residuals) of the previous trees. Unlike Random Forest where trees are independent, Gradient Boosting trees are students in a chain — each one learns from the mistakes of the ones before it.

The algorithm works iteratively: (1) Start with a simple prediction (e.g., the average). (2) Compute the errors (residuals) — how far off each prediction is. (3) Train a new small tree to predict these errors. (4) Add this tree's prediction to the ensemble (scaled by the learning rate). Repeat until the desired number of trees is reached.

Real-World Analogy

"Imagine a classroom where students take turns solving a hard math problem on the whiteboard. The first student gets it mostly right but makes several mistakes. The second student doesn't start from scratch — they only look at the mistakes the first student made and try to fix them. The third student fixes the second student's remaining mistakes, and so on. Each student gets progressively better at fixing what's still wrong. After many students, the final answer is excellent."

Strengths
  • Often highest accuracy on structured/tabular data
  • Captures complex non-linear interactions
  • Handles mixed feature types
  • Feature importance is meaningful
  • Strong performance without extensive feature engineering
  • Regularization via learning rate
Weaknesses
  • Sequential — cannot parallelize training
  • Sensitive to hyperparameter tuning
  • Can overfit if too many trees or high learning rate
  • Slower to train than Random Forest
  • Less robust to noise than bagging methods
  • Requires careful early stopping

XGBoost Classifier WINNER

Ensemble (Boosting) 1st Place — 0.814 ROC-AUC

How It Works

XGBoost (eXtreme Gradient Boosting) is an optimized, scalable implementation of gradient boosting. It follows the same sequential ensemble approach as Gradient Boosting but with critical engineering improvements that make it faster, more accurate, and more robust:

  • Regularization — Built-in L1 and L2 regularization prevents overfitting (gradient boosting lacks this)
  • Parallel Processing — Feature splitting is parallelized across CPU cores during training
  • Handling Missing Values — Automatically learns the best direction for missing values at each split
  • Cache Optimization — Efficient memory access patterns for column-based data
  • Pruning — Splits trees using a depth-first approach and prunes branches that don't improve the objective
Real-World Analogy

"If Gradient Boosting is a smart student who learns from mistakes, XGBoost is that same student who also knows how to study efficiently. They have better note-taking systems (cache optimization), can review multiple subjects simultaneously (parallel processing), know when to stop studying a topic before memorizing irrelevant details (regularization), and can handle incomplete information gracefully (missing value handling). Same learning principle, but the execution is optimized."

CatBoost Classifier

Ensemble (Boosting) 2nd Place — 0.809 ROC-AUC

How It Works

CatBoost (Category Boosting) is a gradient boosting algorithm developed by Yandex with a special focus on categorical features. While XGBoost and standard Gradient Boosting require one-hot encoding or label encoding of categories, CatBoost handles them natively using a technique called Ordered Target Statistics.

The key innovation is Ordered Boosting: instead of using the entire training set to compute residuals (which causes data leakage), CatBoost uses a permutation-based approach where each tree is trained only on data points that appeared before it in a random ordering. This eliminates the prediction shift problem inherent in standard gradient boosting.

Real-World Analogy

"Imagine you're training for a tennis tournament. Regular boosting practices with a coach who sees all your past matches before predicting your next weakness — sometimes the coach 'peeks' at your future games, creating an unrealistically optimistic practice plan. CatBoost's Ordered Boosting is like training with a coach who only reviews matches you've already played in strict chronological order. The coach never sees future matches, so their feedback is always honest and realistic. This produces a more reliable training program."

Special: Native Categorical Feature Handling

When a categorical feature (like "country" or "payment method") is encountered, CatBoost converts it to a numeric value using target statistics: it computes the average target value for all previous training examples with the same category. This is done in a way that prevents target leakage — only past data points contribute to the statistic.

Strengths
  • Best native categorical feature handling
  • Ordered Boosting prevents data leakage
  • Built-in regularization (depth, L2)
  • Often requires less hyperparameter tuning
  • Excellent for datasets with many categorical features
  • Built-in overfitting detection with eval set
Weaknesses
  • Can be slower than XGBoost for purely numerical data
  • Larger model size and memory footprint
  • Fewer community resources than XGBoost
  • Less flexible with custom loss functions
  • C++ backend can have compatibility issues
  • Verbose output needs suppression (verbose=False)

Hyperparameters We Tuned

ParameterValues TestedWhat It Controls
iterations 50, 100 Number of boosting iterations. Equivalent to n_estimators in XGBoost. Each iteration adds one tree to the ensemble. CatBoost uses symmetric (oblivious) decision trees.
depth 4, 6 Depth of the trees. CatBoost uses oblivious trees where the same splitting criterion is used at each level. Depth 4 = 16 leaf nodes. Controls model complexity.
learning_rate 0.1, 0.2 Shrinkage applied to each tree. Scales the contribution of each boosting iteration. Lower values require more iterations but yield more stable models.

Why We Included It

CatBoost achieves 0.809 ROC-AUC — very close to XGBoost. Its ordered boosting technique provides a theoretically more sound gradient boosting framework. While our dataset is mostly numerical (V1-V28 from PCA), CatBoost's regularization and ordered boosting still provide competitive performance.

AdaBoost Classifier

Ensemble (Boosting) Lower Performance

How It Works

AdaBoost (Adaptive Boosting) was one of the first practical boosting algorithms. It works by training a sequence of weak learners (typically decision stumps — trees with only 1 split), where each successive learner focuses more on the samples that the previous learners misclassified.

The algorithm assigns a weight to each training sample. Initially, all weights are equal. After each weak learner is trained, misclassified samples get higher weights and correctly classified samples get lower weights. The next learner then focuses its attention on the harder (higher-weight) examples. The final prediction is a weighted vote of all weak learners.

Real-World Analogy

"A teacher notices that on a practice exam, most students got questions 1, 2, 3 right but questions 4 and 5 were difficult. So for the next practice session, the teacher gives extra attention and drill problems on questions 4 and 5 — the ones most students got wrong. After that round, students improve on 4 and 5 but some now struggle with question 3. The teacher adjusts again, focusing on question 3. This adaptive focus on weaknesses continues until the class masters all questions. AdaBoost does the same with data samples — it focuses extra attention on the hardest-to-classify cases."

Strengths
  • Simple and easy to understand
  • Fast training with weak learners
  • Less prone to overfitting than complex models
  • Theoretically well-founded (no-free-lunch connection)
  • Works well with well-tuned weak learners
  • Good for binary classification tasks
Weaknesses
  • Sensitive to noisy data and outliers
  • Weak learners (stumps) may be too simple
  • Can be outperformed by gradient boosting methods
  • Sequential training is slow
  • Limited to weak learners (can't use deep trees)
  • Struggles with highly imbalanced data

ParameterValues TestedWhat It Controls

learning_rate 0.5, 1.0 Shrinkage on each classifier's contribution. Controls how much each new weak learner affects the final vote. Value of 1.0 = full contribution, 0.5 = halved.

AdaBoost is the historical pioneer of boosting algorithms. While it underperforms compared to gradient-based boosting methods, it provides a valuable comparison point. It demonstrates that not all ensemble methods are equal — gradient-based boosting (XGBoost, CatBoost) significantly outperforms weight-based boosting (AdaBoost) on complex real-world tasks.

Ensemble Methods Explained

Understanding the two fundamental approaches: Bagging vs Boosting.

What is an Ensemble?

An ensemble combines multiple "weak" models to create a single "strong" model. The core insight: diversity improves accuracy. Different models make different errors, and by combining them, errors cancel out.

Bagging (Bootstrap Aggregating)

Strategy: Train models in parallel on random data subsets, then vote/average.

Key idea: Reduce variance (overfitting). Each model sees a different random sample, so they overfit to different things. Averaging cancels out the overfitting.

Models: Random Forest

Boosting

Strategy: Train models sequentially, where each model fixes the previous one's mistakes.

Key idea: Reduce bias (underfitting). Each new model focuses on hard cases that previous models got wrong.

Models: XGBoost, CatBoost, Gradient Boosting, AdaBoost

Why ensembles dominate on tabular data: The "no free lunch" theorem says no model is universally best. Ensembles hedge against this by combining diverse models. Neural networks dominate unstructured data (images, text), but for rows and columns of numbers, gradient boosting is king.

GridSearchCV Hyperparameter Tuning

How we found the optimal configuration for each model using exhaustive search.

What is GridSearchCV?

GridSearchCV is an exhaustive hyperparameter optimization technique from scikit-learn. It systematically tries every possible combination of specified hyperparameter values and evaluates each combination using cross-validation. The combination with the best average cross-validation score is selected as the optimal configuration.

Real-World Analogy

"Imagine you're tuning a radio. You have two dials: volume and bass. Volume can be set to 3, 5, or 7. Bass can be set to low, medium, or high. Instead of guessing, you methodically try every combination: (3,low), (3,medium), (3,high), (5,low), (5,medium), (5,high), (7,low), (7,medium), (7,high) — that's 9 combinations. For each, you listen to a song and rate the sound quality. After trying all 9, you pick the best one. GridSearchCV does exactly this, but with machine learning hyperparameters and cross-validation instead of your ears."

Cross-Validation: cv=2 (2-Fold)

Cross-validation evaluates each hyperparameter combination by splits rather than a single train-test split. With cv=2, the training data is divided into 2 folds. The model is trained on fold 1 and tested on fold 2, then trained on fold 2 and tested on fold 1. The average score across both folds is reported.

2-Fold Cross Validation (cv=2)
Fold 1 (Train on fold 1, validate on fold 2)
TRAIN (50%)
VALIDATE (50%)
Fold 2 (Train on fold 2, validate on fold 1)
VALIDATE (50%)
TRAIN (50%)
Final Score = (Score Fold 1 + Score Fold 2) / 2

Why cv=2 instead of cv=5? With 284K samples, even a 50% split gives ~142K validation samples — more than enough for reliable evaluation. cv=2 is chosen for speed: it cuts training time nearly in half compared to cv=5, while still providing a reasonable estimate of model performance. With GridSearchCV testing 39 parameter combinations, each with 2 folds, that's 78 total model fits — keeping it manageable.

Why scoring='roc_auc'?

We use ROC-AUC (Receiver Operating Characteristic - Area Under Curve) as our scoring metric because it's the ideal metric for imbalanced binary classification. Here's why:

  • Class imbalance: Only ~0.172% of transactions are fraudulent (172 out of 84,807 in test set). Accuracy is misleading — a model that predicts "all legitimate" would be 99.83% accurate but catch zero fraud.
  • ROC-AUC measures ranking quality: It evaluates how well the model separates classes — does it assign higher probabilities to actual fraud than to legitimate transactions?
  • Threshold-independent: ROC-AUC evaluates across all classification thresholds, not just 0.5. This gives a complete picture of model capability.
  • Scale-invariant: It measures the quality of relative predictions, not absolute values.

The Exhaustive Search Process: Step by Step

1
Define Models & Grids — 6 models, each with its hyperparameter dictionary (from model_trainer.py lines 43-83)
2
For each model — Generate all combinations from its parameter grid (e.g., RF: 8 combinations)
3
For each combination — Create model instance with those hyperparameters
4
For each fold (cv=2) — Split training data, train on fold 1, evaluate on fold 2, then swap
5
Average fold scores — Record the mean ROC-AUC for this parameter combination
6
Select best — The combination with the highest average ROC-AUC becomes the model's best_estimator_

The Complete Evaluation Code (from utils.py)

src/utils.py — evaluate_models() 
def evaluate_models(X_train, y_train, X_test, y_test, models, param):
    # Initialize dictionaries to store results
    report = {}
    fitted_models = {}

    # Iterate through all 6 models
    for i in range(len(list(models))):
        model_name = list(models.keys())[i]
        model = list(models.values())[i]
        para = param[model_name]

        # If hyperparameters exist, run GridSearchCV
        if len(para) > 0:
            gs = GridSearchCV(
                model,
                para,
                cv=2,                  # 2-fold cross-validation
                scoring='roc_auc',      # ROC-AUC metric
                n_jobs=-1,              # Parallelize across cores
                verbose=0,
                error_score='raise'
            )
            gs.fit(X_train, y_train)
            best_model = gs.best_estimator_
        else:
            best_model = model
            best_model.fit(X_train, y_train)

        # Store the fitted model
        fitted_models[model_name] = best_model

        # Evaluate on test set
        y_test_prob = best_model.predict_proba(X_test)[:, 1]
        test_roc_auc = roc_auc_score(y_test, y_test_prob)

        # Store ROC-AUC score
        report[model_name] = test_roc_auc

    return report, fitted_models

Why Gradient Boosting Wins on Tabular Data

  • Sequential error correction: Each tree focuses on what previous trees missed, creating a highly adaptive model that captures subtle fraud patterns.
  • Feature interactions: Gradient boosting automatically captures complex feature interactions (e.g., high transaction amount + unusual time + specific V-feature patterns) that linear models can't express.
  • Regularization: XGBoost's built-in L1/L2 regularization prevents overfitting on the imbalanced dataset, while AdaBoost lacks this mechanism.
  • Optimized engineering: XGBoost's parallelized split-finding, cache-efficient data structures, and automatic missing value handling give it a computational edge.
  • Handling imbalance: Tree-based models naturally handle imbalanced classes through their split criteria, while logistic regression requires careful calibration.

Why the Top 3 Differ

XGBoost (0.814)

Regularized boosting + optimized C++ implementation. Best balance of bias reduction and overfitting prevention. The engineering quality makes the difference.

CatBoost (0.809)

Ordered Boosting theoretically prevents data leakage better. Close to XGBoost because our dataset is mostly numerical — CatBoost's categorical advantage doesn't apply here.

Random Forest (0.806)

Bagging reduces variance but doesn't reduce bias. Each tree is independent and makes similar errors on hard cases. Boosting's sequential error correction gives it the edge.

Gradient Boosting (0.803)

Same boosting principle as XGBoost but without regularization or optimized split-finding. The 0.011 gap to XGBoost shows the value of these engineering improvements.

Why Not Other Models?

Reasons we excluded common ML algorithms from our comparison.

Model Why Excluded When It Would Be Useful
Support Vector Machine (SVM) Training complexity is O(n²) to O(n³). With 227,845 training samples, SVM would take hours to days to train. Unusable for GridSearchCV with multiple hyperparameter combinations. Small datasets (<10K samples), text classification with high-dimensional sparse features.
K-Nearest Neighbors (KNN) Subject to the curse of dimensionality. With 29 features (V1-V28 + Amount), distance metrics become less meaningful. Also very slow for prediction — must compute distances to all training points. Low-dimensional datasets, recommendation systems, anomaly detection with few features.
Neural Networks (MLP/DNN) Overkill for structured/tabular data. Neural networks excel at unstructured data (images, text, audio) but gradient boosting consistently outperforms them on tabular datasets. Also requires more data, more tuning, and more compute. Image classification, NLP, speech recognition, large-scale unstructured data.
Naive Bayes Assumes feature independence. Our V1-V28 features (from PCA of correlated features) violate this assumption. The "naive" independence assumption leads to poor probability estimates on correlated features. Text classification (spam detection), document categorization, when features are truly independent.
Decision Tree (Single) Too prone to overfitting. A single tree memorizes training data patterns (including noise). Ensemble methods (Random Forest, XGBoost) use many trees to overcome this weakness. When interpretability is paramount, feature exploration, baseline for ensemble methods.

Key takeaway: Model selection isn't just about accuracy — it's about the right tool for the job. For tabular/structured data with moderate size (like our credit card dataset), gradient boosting methods (XGBoost, CatBoost, LightGBM) are the industry standard. Neural networks would be the choice if we had raw transaction descriptions (text) or wanted to combine structured data with customer behavior sequences.
