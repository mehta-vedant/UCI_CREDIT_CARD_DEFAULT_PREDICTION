Preprocessing and feature engineering

The active sklearn transformer turns 23 supplied raw features into 42 model columns.

IMPLEMENTEDactive root evidence
CONCEPTUALclearly labelled context
LIMITATIONnever fabricated

What this means

Actual order: drop ID; map EDUCATION 0/5/6→4 and MARRIAGE 0→3; create utilisation, six payment ratios, payment-status summaries, bill/payment means and slopes, flags; select 16 engineered values; then impute, encode and scale. consecutive_delays is calculated but omitted, while months_with_delays uses the same count and is selected.

StandardScaler computes (x−training mean)/training standard deviation. MinMaxScaler maps a range, RobustScaler uses median/IQR; neither is active. Fitting transformers on test data leaks information. Root fitting is train-only, but preprocessing sits outside GridSearchCV folds: improve with one estimator+preprocessor pipeline.

Walk one client through the transformer

Suppose a new client has a limit of 100,000, a latest bill of 50,000, and paid 10,000. The feature engineer can create utilisation of 0.50 and a latest payment ratio of 0.20. It also looks across six months to calculate averages, the largest repayment delay, and simple line slopes. These derived values do not add new outside information. They reorganise information already present in the six monthly fields into forms a model may find easier to use.

Next, the numerical pipeline fills a missing numerical value with the training-set median if one appears. The category pipeline fills a missing category with the most frequent training category. These are fallback rules. They are not evidence that a missing value genuinely equals the median or mode. In a real service, a missing or impossible user input often deserves a validation error instead of quiet imputation.

Encoding and scaling slowly

One-hot encoding turns a category into yes/no columns. After drop='first', one category is used as a reference and is represented when the other category columns are all zero. Standard scaling changes the units so that, for example, an amount in hundreds of thousands does not numerically dwarf age. It is especially helpful for linear models. Tree models generally do not need it, but using the same transformed data keeps the six-model comparison consistent.

Why save the preprocessor

The saved CatBoost model was trained on a particular order of 42 transformed columns. If a new app creates columns differently, even a perfectly valid client profile can be interpreted incorrectly. Saving and reusing the preprocessor makes inference reproduce the same category mapping, median values, scaling numbers, feature formulas, and column order used during training.

Check understanding

Try each aloud before opening it: five beginner, five intermediate and two challenging questions.

Beginner — What is the target?

default.payment.next.month: 1 means default, 0 no default.

Beginner — Is this transaction fraud?

No. Root project is next-month client default prediction.

Beginner — What is a feature?

An input clue such as PAY_0 or LIMIT_BAL.

Beginner — Why test data?

To estimate performance on records not used to fit.

Beginner — What limitation matters?

It is historical Taiwan 2005 data, not production lending data.

Intermediate — Evidence for claim?

Cite active root source, paired artifacts, data inspection or recomputed metrics.

Intermediate — What ranks thresholds?

ROC-AUC; active GridSearchCV uses it.

Intermediate — Why can accuracy mislead?

Always predicting no default yields 77.88% accuracy and zero recalls.

Intermediate — What is leakage?

Evaluation/future information influences fitting.

Intermediate — What must accompany model.pkl?

preprocessor.pkl because it produces the expected 42 features.

Challenge — Best improvement?

Select on train-only stratified CV, reserve test, then choose threshold/calibration by cost.

Challenge — Interview summary?

Educational default-risk prototype with evidence-based limits, not a production decision system.
