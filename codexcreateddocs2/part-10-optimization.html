Grid search and selection

Parameters are learned during fit; hyperparameters such as depth and iteration count are choices searched around fit.

IMPLEMENTEDactive root evidence
CONCEPTUALclearly labelled context
LIMITATIONnever fabricated

What this means

evaluate_models creates GridSearchCV(model, grid, cv=2, scoring="roc_auc", n_jobs=-1) for each of six families, fits transformed train data, stores best estimators and records test ROC-AUC. The trainer chooses maximum test ROC-AUC and serialises that model.

Evidence and detail

ChoiceAssessment
ROC-AUC scoringReasonable ranking objective, but not cost/recall threshold policy.
cv=2Fast, but less stable; code does not set StratifiedKFold.
No early stoppingFixed grid, no validation-based stopping.
Max test score selects winnerMain concern: test is no longer strictly final untouched evaluation.

Better: stratified train/test split; Pipeline(preprocess, model); stratified CV/search only in train; choose/calibrate threshold on validation; report once on untouched test. Grid search is exhaustive only over supplied small grids; RandomizedSearchCV can explore larger spaces.

What GridSearchCV is doing behind the scenes

A grid is simply a small menu of choices. For CatBoost, the active code tries two iteration counts, two depths and two learning rates. GridSearchCV makes each combination, trains it on one fold, scores it on the other, swaps the folds, and compares the score. The "best" setting means best under that chosen grid, score and fold arrangement. It does not mean mathematically optimal among every possible CatBoost configuration.

The same applies to model selection. The code does not prove CatBoost is always better than the other five algorithms. It proves that, in the saved run, CatBoost was the selected artifact after the specified small searches and test-score comparison. That is a precise and defensible statement.

The test-set issue explained

A final test set should be like a sealed exam paper. If you look at the scores of six candidates on it and select the highest one, the selection process has learned something from that exam. The winning score can be slightly lucky. A better workflow uses only training data and cross-validation or a validation split to choose the algorithm and settings. Then it opens the test set once to report the final unbiased estimate.

Useful next experiments

Use a stratified split so positive proportion stays stable. Try a larger, justified search space. Compare average precision, recall at a fixed review capacity, calibration, and cost-sensitive metrics. Record every run with data version, seed, features, parameters and scores. These are recommendations. They are not currently implemented.

An input clue such as PAY_0 or LIMIT_BAL.

Beginner — Why test data?

To estimate performance on records not used to fit.

It is historical Taiwan 2005 data, not production lending data.

Intermediate — Evidence for claim?

Cite active root source, paired artifacts, data inspection or recomputed metrics.

ROC-AUC; active GridSearchCV uses it.

Always predicting no default yields 77.88% accuracy and zero recalls.

Intermediate — What is leakage?

preprocessor.pkl because it produces the expected 42 features.
