Read the four matrix cells as stories

A true negative is a client who did not default and was not flagged. A false positive is a client who did not default but was flagged. A false negative is a client who defaulted but was missed. A true positive is a client who defaulted and was flagged. The current saved confusion matrix has 841 false negatives and 238 false positives. Whether that is acceptable depends on what happens after a flag. Is there a human review? Does a flag harm a person? What is the cost of missing a default? The repository does not answer those policy questions.

Precision focuses on the flag: when the model says default, how often is it correct? Recall starts with real defaults: how many were found? F1 compresses both into one number, but it cannot replace the separate values because different use cases value different trade-offs. Specificity covers the other side, asking how well no-default cases are recognised.

Why curves matter

A hard threshold turns a smooth score into a yes/no decision. Move the threshold downward and more rows become positive. ROC-AUC avoids picking one threshold: it asks whether the model generally ranks a random default above a random non-default. A precision-recall curve is especially helpful when positives are less common because it keeps attention on the quality and coverage of positive flags.

Probability quality

Log loss rewards the model for assigning high probability to the event that actually occurred and penalises confident mistakes. Calibration checks whether the numerical scores match reality. A model can rank cases well and still be poorly calibrated. This project reports verified log loss, but it does not include a calibration study. That is why a displayed percentage should be described as the model's score, not as a guaranteed personal likelihood.
