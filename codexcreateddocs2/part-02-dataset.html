The verified UCI dataset

The active ingestion code reads notebooks/data/UCI_Credit_Card.csv. These facts were recomputed from that file.

What this means

The file has 30,000 rows and 25 columns; 23,364 no-default cases (77.88%) and 6,636 defaults (22.12%); zero raw missing cells, duplicate rows and duplicate IDs. It records Taiwan credit-card clients and six months in 2005. Numeric storage does not make codes continuous: SEX, EDUCATION and MARRIAGE are categories.

How to read one row

Think of a row as one client snapshot. LIMIT_BAL is the approved ceiling in New Taiwan dollars. BILL_AMT1 is the most recent statement balance, while PAY_AMT1 is the amount paid for that period. The six PAY columns describe repayment status over time. A recent delay can be more informative than a bill by itself because it records whether payment obligations were met.

The suffixes are easy to mix up. In this data, 1 is the most recent month for bill/payment amounts, then 2, 3 and so on go backward. The repayment columns have the unusual names PAY_0, PAY_2, PAY_3 through PAY_6. That naming comes from the source data; the active project keeps it. Do not silently rename a column unless every input path, trained artifact and test is updated too.

Categories versus numbers

SEX is stored as 1 or 2, but adding or averaging those values has no natural meaning. EDUCATION and MARRIAGE work the same way. They are codes for groups. By contrast, age, bill amount and payment amount have numerical size, so operations such as mean and standard deviation make sense. Repayment-status codes sit in the middle: the project treats them as ordered numerical values because higher positive delay codes represent more delay. That is a modelling decision worth discussing in an interview.

What the raw checks tell us

Zero missing cells and zero duplicate rows are good starting facts, not proof that the data is clean or representative. A value can be present and still be inaccurate, out of date, biased, or recorded under an unclear definition. The unusual raw education and marriage codes are an example: there is a number in the cell, but the project still has to decide what that number means.

Check understanding

Try each aloud before opening it: five beginner, five intermediate and two challenging questions.

Beginner — What is the target?

default.payment.next.month: 1 means default, 0 no default.

Beginner — Is this transaction fraud?

No. Root project is next-month client default prediction.

Beginner — What is a feature?

An input clue such as PAY_0 or LIMIT_BAL.

Beginner — Why test data?

To estimate performance on records not used to fit.

Beginner — What limitation matters?

It is historical Taiwan 2005 data, not production lending data.

Intermediate — Evidence for claim?

Cite active root source, paired artifacts, data inspection or recomputed metrics.

Intermediate — What ranks thresholds?

ROC-AUC; active GridSearchCV uses it.

Intermediate — Why can accuracy mislead?

Always predicting no default yields 77.88% accuracy and zero recalls.

Intermediate — What is leakage?

Evaluation/future information influences fitting.

Intermediate — What must accompany model.pkl?

preprocessor.pkl because it produces the expected 42 features.

Challenge — Best improvement?

Select on train-only stratified CV, reserve test, then choose threshold/calibration by cost.

Challenge — Interview summary?

Educational default-risk prototype with evidence-based limits, not a production decision system.
