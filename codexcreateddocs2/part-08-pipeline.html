What this means

Run src/pipeline/train_pipeline.py: DataIngestion writes raw/train/test CSVs; DataTransformation fits preprocessor on train and transforms test; ModelTrainer grid-searches six models and saves winner. PredictPipeline loads paired pickles, transforms a one-row DataFrame and uses predict/predict_proba. Flask/API/Next interfaces call it.

Training and prediction are different jobs

Training happens occasionally. It reads known historical outcomes, learns preprocessing statistics and model parameters, then writes artifacts. Prediction happens repeatedly. It receives one client profile without a known target, applies the already learned preprocessor, and asks the saved model for a class and probability. Mixing these jobs is a common beginner mistake. A prediction endpoint must not refit the model or scaler on the incoming client.

The root project has a practical modular design. Ingestion owns file reading and splitting. Transformation owns feature construction. Training owns model selection. The prediction class owns artifact loading and scoring. The Flask form and JSON handler mainly translate user input into the exact 23-field DataFrame expected by the preprocessor. This separation makes the flow easier to trace and test.

Why pipelines are more than neat organisation

A pipeline turns a sequence of fragile manual steps into one object with a repeatable contract. It keeps fitting and transformation order consistent. A ColumnTransformer makes the contract explicit: these fields are numerical, these are categorical, and every remaining field is dropped. A stronger version would put the estimator in the same pipeline before cross-validation so each CV fold learns imputation, encoding and scaling from its own training portion.

What inference returns

predict() gives the hard 0/1 decision using the model's current default threshold. predict_proba() gives two probabilities, one per class. The code selects column 1 as the default probability. The UI also groups the score into low, moderate and high display bands. Those bands help presentation, but they do not change the prediction threshold.

Check understanding

Try each aloud before opening it: five beginner, five intermediate and two challenging questions.

Beginner — What is the target?

default.payment.next.month: 1 means default, 0 no default.

Beginner — Is this transaction fraud?

No. Root project is next-month client default prediction.

Beginner — What is a feature?

An input clue such as PAY_0 or LIMIT_BAL.

Beginner — Why test data?

To estimate performance on records not used to fit.

Beginner — What limitation matters?

It is historical Taiwan 2005 data, not production lending data.

Intermediate — Evidence for claim?

Cite active root source, paired artifacts, data inspection or recomputed metrics.

Intermediate — What ranks thresholds?

ROC-AUC; active GridSearchCV uses it.

Intermediate — Why can accuracy mislead?

Always predicting no default yields 77.88% accuracy and zero recalls.

Intermediate — What is leakage?

Evaluation/future information influences fitting.

Intermediate — What must accompany model.pkl?

preprocessor.pkl because it produces the expected 42 features.

Challenge — Best improvement?

Select on train-only stratified CV, reserve test, then choose threshold/calibration by cost.

Challenge — Interview summary?

Educational default-risk prototype with evidence-based limits, not a production decision system.
