8. Training, search, and selection

How the program avoids choosing a model only because it got lucky on one split.

The actual execution order

load CSV→remove ID→60/20/20 split→3-fold CV on training→select model→validation threshold→test once

train_test_split(..., stratify=y, random_state=42) keeps class proportions similar and makes the split repeatable. A seed is not a quality guarantee; it simply lets another person repeat the same draw.

GridSearchCV in ordinary language

Within the 18,000-row training partition, StratifiedKFold makes three shuffled folds in the normal run. For each candidate setting, GridSearchCV fits the complete preprocessing-and-model pipeline on two folds and scores it on the held-out fold, rotating until each fold has been held out. It averages the scores before ranking settings.

The script calculates ROC-AUC, average precision, and F1. It sets refit="roc_auc", which means select settings on mean ROC-AUC and then fit those settings on all training rows. Validation and test data remain outside that search.

Repeatable outputs

The normal command is python -m src.credit_risk.training --seed 42. It saves the full fitted pipeline at models/credit_risk_pipeline.joblib, metadata at models/model_metadata.json, and report figures/metrics. --full-search uses a broader five-fold search and takes longer. The saved full pipeline prevents the website from applying preprocessing differently than training did.

The grid is finite and does not prove global optimality. A stronger production study would use time-aware evaluation where timestamps exist, calibration review, monitoring, and an operating threshold chosen with actual review costs.

Why not select based on test performance?

Choosing after seeing test results turns the test set into part of tuning. The script chooses model in cross-validation and threshold on validation, then reports test metrics afterward.
