6. Class imbalance and the threshold

Why a respectable accuracy can hide an unhelpful credit-risk model.

The imbalance in this dataset

There are 23,364 non-default records and 6,636 default records. “No default” is the majority class. A lazy model that always predicts no default would be correct 77.88% of the time, while finding zero people who default. That is why accuracy is not enough here.

What this project actually does

IMPLEMENTED

During search, logistic regression uses class_weight="balanced" and random forest uses class_weight="balanced_subsample". These increase the fitting cost of minority-class errors. The selected CatBoost candidate is evaluated through its configured grid. The project does not use SMOTE, ADASYN, or random over/under-sampling.

After selecting the model, the script tests thresholds from 0.05 to 0.95 in steps of 0.005 on the validation partition and chooses the highest validation F1. It selected 0.245. The live application marks “review recommended” when probability is at least 24.5%.

Threshold changes the result

At 0.50, only high estimated risks get a flag. Lowering it to 0.245 catches more known defaults (higher recall), but flags more clients who would not default (lower precision). The correct trade-off depends on review capacity, fairness, the cost of a missed default, and probability calibration. F1 is a clear reproducible rule here; it is not a universal business policy.

Never resample validation or test data. If SMOTE were added, it would run only inside each cross-validation training fold through an imbalanced-learn pipeline.

What is F1?

F1 = 2 × precision × recall / (precision + recall). The harmonic mean falls quickly if either precision or recall is weak.
