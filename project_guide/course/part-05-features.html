5. Preparing the information

Every transformation in the fitted pipeline, with the reason it exists.

Raw inputs become useful features

A feature is a piece of information a model can use. Feature engineering creates meaningful summaries from existing past data. It is like giving a doctor a six-month average and trend rather than asking them to mentally combine six separate readings. The project's transformer starts with 23 raw client inputs and makes these additional inputs.

The past-only rule

Every engineered feature comes from fields available before the next-month target. A feature created from a future bill or the default label would cheat. This is temporal leakage. The code deliberately builds ratios, summaries, flags, and trends only from supplied historical months.

Cleaning and encoding

The transformer maps unusual source codes EDUCATION 0, 5, and 6 to 4, and MARRIAGE 0 to 3. This groups irregular codes into an “other” category rather than treating codes as ordered amounts. Categorical fields use a most-frequent-value imputer and one-hot encoding with the first category dropped. One-hot encoding turns a category into yes/no columns because arithmetic on labels is misleading.

Imputation and scaling

The active CSV has no missing cells, yet numerical columns use a median imputer and categorical columns use a mode imputer. This keeps training and prediction behaviour consistent if a permissible future input is missing. Numeric columns then use StandardScaler: subtract the training mean and divide by training standard deviation. Large currency amounts and small status codes therefore have comparable scale for logistic regression.

Normalization commonly squeezes values into 0–1 with MinMaxScaler. RobustScaler uses median and interquartile range, so outliers influence it less. Those are alternatives, not active transformations. Trees do not need scaling, but a shared pipeline keeps all candidates consistent.

The imputer, scaler, and encoder learn only from training folds. If a test row contributes to a median or mean, information from the final exam leaks backward. Scikit-learn Pipeline controls when each step is fitted.

The trained pipeline accepts new client data through predict_proba and returns the probability for class 1.

What happens to a new category?

The encoder uses handle_unknown="ignore". It does not crash; it leaves known dummy columns at zero. Monitoring should still flag repeated unseen values.
