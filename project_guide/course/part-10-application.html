What happens on form submit?

23 values→validation→cached joblib→feature transformer→preprocessor→CatBoost probability→0.245 review rule

src/credit_risk/inference.py validates the payload, loads the saved pipeline and metadata, calls predict_proba, and returns probability plus label. application.py does not recreate features by hand. Training and serving use the same serialised object.

Run and deploy

Follow the root README: create/activate a Python 3.11 environment, install requirements-dev.txt, train, generate explainability/showcase assets, run tests, then start python application.py. The Dockerfile builds a container and starts Gunicorn with the platform PORT. Build locally with docker build -t credit-risk . and run with docker run -p 5000:5000 credit-risk.

Hosting choice

This is a Flask server, not a static Vercel site. Deploy the Docker image to a container host such as Render, Railway, Fly.io, Google Cloud Run, or an equivalent platform. The documentation can come from the same Flask app. Choose based on cost, sleeping policy, logs, region, and future database needs.

Production gaps

RECOMMENDED BEFORE REAL USE
  • Add authentication, rate limiting, CSRF protection, structured logs, and secrets management.
  • Use formal request schemas and tighter input-range validation.
  • Monitor drift, calibration, outcome feedback, latency, and errors.
  • Define human review, fairness assessment, adverse-action, and retraining governance.
Can users reproduce the results?

They can clone the repository, install pinned dependencies, run training with seed 42, and compare reports. Exact values can still vary slightly by library and platform version.
