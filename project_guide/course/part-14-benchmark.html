How the broad benchmark earns its conclusion

This chapter explains the stronger experiment behind the live application. It tells you what was compared, in what order, and why the final test set was protected.

IMPLEMENTED IN THE PROJECT

Why run a benchmark at all?

Choosing a model because its name sounds advanced is not engineering. A benchmark gives several different kinds of learner the same data, the same engineered inputs, the same stratified folds, and the same scoring rule. It asks a fair question: which approach ranks likely defaults most usefully before we choose a business action?

The command python -m src.credit_risk.benchmark --seed 42 --n-iter 10 screens thirteen candidates: a dummy baseline, linear, distance-based, probabilistic, single-tree, bagged-tree, boosting, CatBoost, and XGBoost models. It then tunes only the four strongest non-baseline candidates. This reduces wasted compute while keeping the choice evidence-led.

Start with the deliberately simple baseline

The dummy classifier predicts the class frequency rather than learning customer patterns. Because 22.12% of records are defaults, its average precision is about 0.221. That number is a useful floor: a serious ranking model should substantially improve on it. Accuracy would be misleading here because a model predicting “no default” for everyone would be roughly 77.88% accurate while catching no defaults at all.

Interview sentence: “I used average precision as the primary selection metric because it focuses on whether the records the model ranks as risky are actually defaults, which is more informative than raw accuracy under a 22% positive rate. I retained ROC-AUC, log loss, precision, recall, F1, and calibration diagnostics because one metric cannot describe every trade-off.”

What five-fold stratified cross-validation means

Imagine shuffling the training set into five similar piles while keeping the default proportion similar in each pile. The model trains on four piles and scores the fifth. It repeats until every pile has served as the held-out fold. The benchmark averages those five scores. This is more reliable than being lucky or unlucky with one train/validation split.

All preprocessing is inside the pipeline. In each fold, imputation, scaling, one-hot encoding, and any resampling learn only from that fold’s training rows. This is crucial: fitting them before the split would let information from the held-out rows influence training, a mistake called leakage.

Why tuning comes after screening

Hyperparameters are settings chosen before fitting, such as tree depth, learning rate, number of trees, regularisation, or the number of neighbours. RandomizedSearchCV samples sensible combinations for each finalist and repeats the same five-fold evaluation. It does not search every possible combination; that would cost far more computation and can encourage trial-and-error overfitting.

How imbalance is tested honestly

The winner is not assumed to need synthetic data. The code compares its native class handling, random oversampling, and SMOTENC. Random oversampling duplicates minority training examples. SMOTENC makes synthetic default examples while treating specified category codes as categories. Both are placed inside an imbalanced-learn pipeline, so validation and test records are never copied or synthesised.

Ranking is not an action: choose a threshold separately

A probability model gives each client a score from zero to one. A threshold turns that score into a review flag. The project selects the F1-maximising threshold using validation rows only, after model selection. F1 balances precision (how credible flags are) and recall (how many defaults are caught). A bank could deliberately choose a different threshold after measuring review capacity and the cost of missed defaults versus unnecessary reviews.

The protected final test

The final 6,000-row test partition is not used to pick a model, tune a setting, choose a sampling method, or select a threshold. It is opened once at the end. Its metrics estimate how the fixed procedure might generalise to unseen rows from the same historical dataset. They do not prove production performance, fairness, causation, or suitability for automated credit decisions.

Check your understanding

Why is a dummy baseline useful?

It tells you the score achievable without learning a relationship. Here, the positive-class rate is the no-skill average-precision reference.

Why not choose the model on final test F1?

Repeatedly choosing based on the final test causes test-set overfitting. Use cross-validation for model selection, validation for threshold choice, and reserve the test for the final report.

Can SMOTENC be applied before splitting?

No. Synthetic points could be influenced by rows that later become validation or test data. It belongs inside the training portion of each fold.
