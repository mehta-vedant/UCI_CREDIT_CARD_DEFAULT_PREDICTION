Python concepts as they appear

An import brings a class or function from another module. A function is a named reusable operation. A class is a template for objects with data and methods. A pandas DataFrame is a labelled table, like a spreadsheet in memory. A NumPy array is a compact numerical grid. A method such as frame.copy() is a function attached to an object.

The training file

Training reads the CSV into a DataFrame, separates X features from y target, and removes ID. It creates stratified train/validation/test partitions. For each candidate, it builds a pipeline whose first step is the feature/preprocessing transformer and whose final step is the estimator. GridSearchCV fits and scores candidate parameter combinations. The selected pipeline predicts validation probabilities so threshold selection can happen without touching test data. Finally it evaluates test predictions, serialises the pipeline with joblib, stores JSON metadata, and asks the showcase module to refresh aggregate charts.

The inference file

load_assets() caches the joblib pipeline and metadata so the server does not read them afresh for every request. predict() checks that all expected client fields arrive, converts the values to a one-row DataFrame, asks for class-1 probability, compares it with metadata threshold, and constructs a plain response. Separating this from Flask means a script, API, and form can all use the same prediction logic.

Why serialization matters

Joblib serialisation saves Python objects to disk. Here it saves the fitted feature transformer, encoders, scaler, and CatBoost model together. Saving only the CatBoost object would invite training-serving skew: a web app could calculate columns in a different order or scale values differently. Loading untrusted joblib files is unsafe, so only load an artifact produced and controlled by this project.

Tests

pytest -q runs automated checks. The tests verify feature calculations, input handling, project-page behaviour, and showcase output. Tests reduce regressions; they do not prove the ML model is fair, calibrated, or suitable for lending decisions.

Why use a custom transformer?

It lets feature engineering live inside sklearn's fit/transform lifecycle. Cross-validation can therefore refit feature steps inside each fold, instead of reusing information calculated from all rows.
